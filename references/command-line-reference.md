# Command-Line Reference

## Purpose

This is the complete index of supported Python command-line entry points. It
explains where each command belongs and how to discover every invocation-only
parameter. The executable parser is the exact contract: run the command shown
in the **Help** column before operating it, and run subcommand help when listed.

Environment-backed defaults are defined separately in
[`runtime-configuration.md`](runtime-configuration.md). Artifact shapes,
required companion files, and no-clobber behavior are defined in
[`artifact-contracts.md`](artifact-contracts.md). If prose and executable help
ever disagree, stop the run and correct both; do not guess which behavior was
intended.

Every argument of every command carries help text. Recurring option names —
`--out`, `--exceptions`, `--raw-dir`, `--model`, `--enable` and the rest — take
their wording from one canonical vocabulary in `scripts/cli_help.py`, so the same
option means the same thing in every parser that uses it. An option whose meaning
genuinely differs in one command states its own wording there and keeps it.
`scripts/release_check.py` fails if any argument neither carries inline help nor
appears in that vocabulary, which is what keeps this page's promise true.

For the complete flag-level technical appendix, use
[`cli-help-catalogue.md`](cli-help-catalogue.md). It contains the checked-in,
parser-derived `--help` content for every supported command and subcommand:
positional inputs, every option, defaults, choices, and descriptions. Only the
visual wrapping of each `usage:` synopsis is normalized so the catalogue remains
stable across supported CPython versions. The release check regenerates the
same text in memory and rejects a stale catalogue.
This page remains the concise command, phase, and safety index; the catalogue
is the detailed option reference.

## How parameters work

- Positional arguments identify retained inputs. They are required unless the
  usage line encloses them in brackets.
- `--out`, `--exceptions`, `--raw-dir`, `--adapter-out`, `--handoff-out`, and
  similar options create run-scoped artifacts. Use a new path and preserve the
  prior output.
- Boolean controls are explicit opt-ins. Where both positive and negative
  forms exist, the last explicit CLI form overrides environment configuration.
- Numeric limits are hard safety or resource bounds, not confidence or accuracy
  guarantees. Invalid ranges fail before work begins.
- `--enable`, `--execute`, remote-provider, and listener options cross a local or
  external-state boundary. Use them only with the named client authorization.
- For a full run, record the named transmission scope before the first provider
  invocation in non-secret `RUN/logs/run_authorization.md`; authorization of all
  in-scope sends does not authorize accepting proposals or production actions.
- `--quiet` changes console output only; it does not suppress retained findings.
- `--resume`, `--resume-from`, and `--resume-raw-dir` may reuse verified prior
  work. They never authorize overwriting an existing canonical artifact.
- Paths, source files, destination names, materiality, sampling design, bind
  addresses, certificates, and client reference exports belong on the command
  line. Shared provider and policy-safe defaults belong in `.env` or a versioned
  registry as documented.

Vertex will not serve the shared extraction schema unchanged. Its structured
output rejects a schema that branches too widely -- the served refusal names
"objects with lots of optional properties, enums with too many values, or any_of
a large number of alternative types" -- and the extraction schema meets two of
those. `google_genai_adapter.py` therefore translates the schema before sending
it: it drops `additionalProperties` and `minLength`, which Vertex has no
vocabulary for; folds each nullable `anyOf` pair onto its non-null branch with
Vertex's `nullable` flag; and sorts each `required` list without changing its
membership. Those three preserve the constraint exactly.

The fourth does not. An enum longer than the measured 40-value ceiling loses its
`enum` and carries its permitted values in the field description instead, so the
model is asked for one of those values rather than held to them. On the current
schema that applies to exactly one field, the 158 header field names; the whole
vocabulary is carried, and a vocabulary too large to carry is refused rather
than truncated. The OpenAI lane still sends the full enum, so the two engines
are not held to the same vocabulary by the schema, and the retained handoff
names every relaxed field in `response_schema.relaxed_enum_paths`. The
translated schema's own hash takes part in the response-cache key, so a changed
translation cannot replay a response the previous one shaped.

`--max-output-tokens` defaults to the recorded model ceiling
(`GOOGLE_VERTEX_AI_MODEL_MAX_OUTPUT_TOKENS`). A wide commission page carries
fifty required columns over forty rows, and a response truncated mid-object is a
lost page rather than a shorter one.

OpenRouter and Anthropic are selected through `llm_adapter.py`;
`openrouter_adapter.py` and `anthropic_adapter.py` are provider implementations,
not separately documented operator CLIs. Anthropic takes its structured output
from a required tool call, because the Messages API has no strict
`response_format`, and submits a retained page PDF as a document block so the
recorded vendor is the one that read the glyphs.

## Change checklist

When adding or changing a CLI:

1. Give every positional and optional argument a plain-language help string, or
   use one of the recurring names defined in `scripts/cli_help.py` and call
   `apply_shared_help(parser)` before `parse_args`. The release check enforces
   this; an argument cannot ship undocumented.
2. Validate type, range, allowed values, and mutually exclusive choices before
   side effects.
3. Preserve no-clobber, evidence, exception, and proposal-only boundaries.
4. Update this index, the phase reference, and artifact contracts if the
   interface changes.
5. Add success, malformed-input, boundary, and failure-path tests.
6. Run `scripts/release_check.py`; it verifies that every argparse entry point
   remains indexed here.
